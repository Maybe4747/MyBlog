# 技术架构文档

## 系统架构概述

这是一个基于 Node.js + Express + MySQL 的个人职业资料管理平台，采用 RESTful API 架构，支持用户注册、登录、个人资料管理、文件上传、社交互动等功能。

## 技术栈

- **后端**: Node.js + Express.js
- **关系型数据库**: MySQL 8.0+
- **文件存储**: TOS (火山引擎对象存储)
- **其他**: 环境变量管理 (dotenv), JWT 认证, 文件上传 (multer)

## 数据库设计

### MySQL 数据库 (career_platform)

**表结构关系**:
- `users` 表为核心用户表，其他表通过外键关联此表
- `user_profiles`, `user_skills`, `user_experiences`, `user_education`, `user_social_links`, `user_privacy_settings` 等表存储用户扩展信息
- `follows`, `post_likes`, `post_comments`, `article_likes`, `article_comments`, `file_likes`, `file_comments`, `message_likes`, `notifications` 等表处理社交功能
- `posts`, `articles`, `user_files` 表存储用户发布的内容
- `user_sessions` 表处理会话管理
- `system_configs` 表存储系统配置
- `profile_visits` 表记录访客访问

#### 1. users 表 (用户基础信息表)
- **字段**:
  - id (主键, 自增, int)
  - username (用户名, varchar(50), 唯一)
  - email (邮箱, varchar(100), 唯一)
  - passwordHash (密码哈希, varchar(255))
  - avatar (头像URL, varchar(255))
  - created_at (创建时间, timestamp)
  - updated_at (更新时间, timestamp)
  - last_login (最后登录时间, timestamp)

- **用途**: 存储用户的基础认证信息

#### 2. user_profiles 表 (用户档案扩展表)
- **字段**:
  - user_id (外键关联users.id, int, 主键)
  - bio (个人简介, text)
  - location (所在地, varchar(100))
  - website (个人网站, varchar(255))
  - company (公司, varchar(100))
  - position (职位, varchar(100))
  - cover_image (封面图片URL, varchar(255))
  - created_at, updated_at

- **外键关系**: 
  - `FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE`
  
- **用途**: 存储用户的扩展个人信息

#### 3. user_skills 表 (用户技能表)
- **字段**:
  - id (主键, 自增, int)
  - user_id (外键, int)
  - skill_name (技能名称, varchar(100))
  - proficiency (熟练程度, enum: beginner/intermediate/advanced/expert)
  - created_at

- **外键关系**:
  - `FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE`
  
- **约束**: `UNIQUE KEY user_skill (user_id, skill_name)`
  
- **用途**: 记录用户掌握的技能及其熟练度

#### 4. user_experiences 表 (用户工作经历表)
- **字段**:
  - id (主键, 自增, int)
  - user_id (外键, int)
  - company (公司名称, varchar(100))
  - position (职位, varchar(100))
  - start_date (开始日期, date)
  - end_date (结束日期, date, 可为空)
  - description (工作描述, text)
  - created_at

- **外键关系**:
  - `FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE`
  
- **索引**: `KEY idx_user_id (user_id)`
  
- **用途**: 存储用户的工作经历信息
- **排序**: 仍在职的优先，然后按结束时间（如果有）或开始时间降序

#### 5. user_education 表 (用户教育背景表)
- **字段**:
  - id (主键, 自增, int)
  - user_id (外键, int)
  - school (学校名称, varchar(100))

- **外键关系**:
  - `FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE`
  
- **索引**: `KEY idx_user_id (user_id)`
  
- **用途**: 存储用户的教育背景信息

#### 6. user_social_links 表 (用户社交链接表)

- **外键关系**:

### 数据库使用策略

该项目采用了**单一数据库架构**：
- **MySQL**: 存储所有结构化数据和关系数据，如用户基础信息、社交关系、用户技能、工作经历、教育背景、帖子、文章、文件信息、评论内容、通知等

这种架构通过合理的表结构设计和关联关系，实现了数据的统一管理。

### 单一数据库架构设计原理

在用户注册和登录等核心业务场景中采用单一数据库架构的原因：

#### 1. 数据特性统一
- **MySQL (users 表)**: 存储核心认证数据，具有结构化、强一致性要求的特点
- **MySQL (user_profiles 表)**: 存储用户详细信息，具有结构化、可扩展的特点

#### 2. 业务场景分析
在用户注册过程中：
- **MySQL**: 存储基本认证信息（用户名、邮箱、密码）和用户详细资料，提供唯一性约束和事务支持

#### 3. 实现优势
- **事务与一致性**: MySQL 提供 ACID 特性，确保注册过程的原子性
- **性能优化**: 使用单一数据库优化认证和关系数据查询
- **灵活性与扩展性**: 使用关联表和JSON字段提供足够的灵活性，同时保持结构化存储的优势

#### 4. 单一架构优势
- **维护简化**: 使用单一数据库简化部署、备份和维护工作
- **数据一致性**: 避免跨数据库同步问题
- **查询优化**: 通过合理的表结构设计和索引优化查询性能

#### 5. 为什么在用户注册和登录中使用单一数据库

**用户注册** (`POST /api/auth/register`) 使用 MySQL 单一架构的具体原因：

- **事务完整性要求**: 注册过程使用MySQL事务确保数据一致性，使用事务确保在任一操作失败时能够回滚
- **核心认证数据**: MySQL users 表存储关键的认证信息（用户名、邮箱、密码），保证唯一性约束和关系完整性
- **用户资料结构化**: MySQL user_profiles 和相关表存储用户详细信息，支持未来扩展新的用户属性

**用户登录** (`POST /api/auth/login`) 仅使用 MySQL 的原因：

- **登录验证**: 只需验证用户名/邮箱和密码的正确性，这些核心认证信息都存储在 MySQL users 表中
- **性能优化**: 登录是高频操作，直接在 MySQL 中完成验证可以提高性能
- **数据一致性**: 认证信息集中在 MySQL 中，避免任何数据库访问的复杂性

这种设计确保了系统在保持数据一致性的同时，简化了系统架构。

## 接口设计原则

### 统一响应格式
所有接口返回统一的数据格式：
```json
{
  "code": 0,        // 0表示成功，非0表示失败
  "data": {},       // 响应数据
  "msg": "提示信息" // 消息提示
}
```

### 认证机制
- 使用 JWT (JSON Web Token) 进行身份认证
- Token 存储在 HTTP Authorization 头中
- 支持 token 刷新机制

### 中间件
- `cors`: 处理跨域请求
- `helmet`: 安全头设置
- `compression`: 响应压缩
- `morgan`: 日志记录
- `express-rate-limit`: 限流保护
- `cookie-parser`: Cookie 解析
- `express-validator`: 参数验证
- 自定义 `authenticateToken`: JWT 验证中间件
- 自定义 `optionalAuth`: 可选认证中间件

### 错误处理
- 统一错误处理中间件
- 不同类型错误返回相应的 HTTP 状态码
- 生产环境不暴露敏感信息

## 文件存储

### TOS (火山引擎对象存储)
- 用于存储用户上传的头像、封面图片、帖子图片/视频、文件等
- 支持图片和视频的存储和访问
- 文件URL存储在数据库中，通过TOS服务访问

## 性能优化建议

1. **数据库优化**:
   - 合理使用索引
   - 查询优化
   - 读写分离

2. **缓存优化**:
   - API 响应缓存
   - 首页数据缓存（sessionStorage）

3. **文件处理**:
   - 使用 TOS CDN 分发静态文件
   - 图片压缩和格式转换
   - 文件分片上传

4. **前端优化**:
   - 减少 HTTP 请求数量
   - 前端资源压缩
   - 合理使用缓存策略
   - 滚动位置记忆和页面数据缓存

## 安全措施

1. **认证安全**:
   - 密码使用 bcrypt 加密
   - JWT token 有过期时间
   - 支持 token 刷新和注销

2. **输入验证**:
   - 使用 express-validator 验证输入
   - 防止 SQL 注入和 XSS 攻击
   - 文件上传验证

3. **访问控制**:
   - JWT 认证保护私有接口
   - 用户权限控制
   - API 限流保护
   - 内容可见性控制（public/followers/private）

## 代码规范

1. **命名规范**:
   - 变量和函数使用 camelCase
   - 常量使用 UPPER_SNAKE_CASE
   - 类名使用 PascalCase

2. **代码结构**:
   - 按功能模块组织代码
   - 使用 MVC 模式
   - 模型、路由、控制器分离
   - Services 层处理业务逻辑

3. **错误处理**:
   - 统一错误处理机制
   - 详细错误日志
   - 用户友好的错误提示
