# 数据库设计文档

## MySQL 数据库表结构

### 1. users 表 (用户基础信息)
```
+----------------+--------------+------+-----+-------------------+----------------+
| Field          | Type         | Null | Key | Default           | Extra          |
+----------------+--------------+------+-----+-------------------+----------------+
| id             | int          | NO   | PRI | NULL              | auto_increment |
| username       | varchar(50)  | NO   | UNI | NULL              |                |
| email          | varchar(100) | NO   | UNI | NULL              |                |
| passwordHash   | varchar(255) | NO   |     | NULL              |                |
| avatar         | varchar(255) | YES  |     | NULL              |                |
| created_at     | timestamp    | NO   |     | CURRENT_TIMESTAMP |                |
| updated_at     | timestamp    | NO   |     | CURRENT_TIMESTAMP |                |
| last_login     | timestamp    | YES  |     | NULL              |                |
+----------------+--------------+------+-----+-------------------+----------------+
```
- **主键**: id
- **唯一键**: username, email
- **描述**: 存储用户的基础认证信息

### 2. user_profiles 表 (用户档案扩展)
```
+----------------+--------------+------+-----+-------------------+-------+
| Field          | Type         | Null | Key | Default           | Extra |
+----------------+--------------+------+-----+-------------------+-------+
| user_id        | int          | NO   | PRI | NULL              |       |

| location       | varchar(100) | YES  |     | NULL              |       |
| website        | varchar(255) | YES  |     | NULL              |       |
| company        | varchar(100) | YES  |     | NULL              |       |
| position       | varchar(100) | YES  |     | NULL              |       |
| cover_image    | varchar(255) | YES  |     | NULL              |       |
| created_at     | timestamp    | NO   |     | CURRENT_TIMESTAMP |       |
| updated_at     | timestamp    | NO   |     | CURRENT_TIMESTAMP |       |
+----------------+--------------+------+-----+-------------------+-------+
```
- **主键**: user_id
- **外键**: user_id → users(id)
- **描述**: 存储用户的扩展个人信息

### 3. user_skills 表 (用户技能)
```
+----------------+-----------------------------+------+-----+-------------------+----------------+
| Field          | Type                        | Null | Key | Default           | Extra          |

| user_id        | int                         | NO   | MUL | NULL              |                |
| skill_name     | varchar(100)                | NO   |     | NULL              |                |
| proficiency    | enum('beginner','intermediate','advanced','expert') | NO   |     | beginner          |                |

+----------------+-----------------------------+------+-----+-------------------+----------------+
```

- **外键**: user_id → users(id)
- **唯一键**: (user_id, skill_name)

## 数据库使用策略

### MySQL 使用场景
- **用户认证信息**: 存储用户的基本账号信息，如用户名、邮箱、密码哈希
- **关系数据**: 存储用户之间的关系，如关注、点赞等
- **结构化数据**: 存储有明确字段定义的数据，如技能、工作经历、教育背景、帖子、文章、文件等
- **事务性操作**: 需要强一致性保证的场景，如用户注册、数据同步

### 单一数据库架构设计原理

在用户注册和登录等核心业务场景中采用单一数据库架构的原因：

#### 1. 数据特性统一
- **MySQL (users 表)**: 存储核心认证数据，具有结构化、强一致性要求的特点
- **MySQL (user_profiles 表)**: 存储用户详细信息，具有结构化、可扩展的特点

#### 2. 业务场景分析
在用户注册过程中：
- **MySQL**: 存储基本认证信息（用户名、邮箱、密码）和用户详细资料，提供唯一性约束和事务支持

#### 3. 实现优势
- **事务与一致性**: MySQL 提供 ACID 特性，确保注册过程的原子性
- **性能优化**: 使用单一数据库优化认证和关系数据查询
- **灵活性与扩展性**: 使用关联表提供足够的灵活性，同时保持结构化存储的优势

#### 4. 单一架构优势
- **维护简化**: 使用单一数据库简化部署、备份和维护工作
- **数据一致性**: 避免跨数据库同步问题
- **查询优化**: 通过合理的表结构设计和索引优化查询性能

#### 5. 为什么在用户注册和登录中使用单一数据库

**用户注册** (`POST /api/auth/register`) 使用 MySQL 单一架构的具体原因：

- **事务完整性要求**: 注册过程使用MySQL事务确保数据一致性，使用事务确保在任一操作失败时能够回滚
- **核心认证数据**: MySQL users 表存储关键的认证信息（用户名、邮箱、密码），保证唯一性约束和关系完整性
- **用户资料结构化**: MySQL user_profiles 和相关表存储用户详细信息，支持未来扩展新的用户属性

**用户登录** (`POST /api/auth/login`) 仅使用 MySQL 的原因：

- **登录验证**: 只需验证用户名/邮箱和密码的正确性，这些核心认证信息都存储在 MySQL users 表中
- **性能优化**: 登录是高频操作，直接在 MySQL 中完成验证可以提高性能
- **数据一致性**: 认证信息集中在 MySQL 中，避免任何数据库访问的复杂性

这种设计确保了系统在保持数据一致性的同时，简化了系统架构。
